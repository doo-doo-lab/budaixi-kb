# 角色 doc Frontmatter Schema v1

> 状态：草案，未实施。先讨论确认，再写 `yaml_extract.py` 批量加。

## 设计原则

1. **Frontmatter 只放结构化、可查询字段**。正文写自然语言叙述。
2. **多值用 YAML list**（武学/朋友/别名等）。
3. **单值保留原文字符串**，v1 不结构化拆解（`初登场: 霹雳侠峰 第48章` 不拆 series/episode）。
4. **厂牌从目录推**（pili/jinguang/dongli），**不写入** frontmatter。
5. **避免覆盖 MkDocs Material 保留字段**：`title` / `description` / `tags` / `hide` 不要用作角色字段名，用中文 key。
6. **可选字段缺失 = 字段不出现**（不要写 `初登场: null`）。
7. **数据来源同 frontmatter 不必同正文一致**：frontmatter 是查询索引，正文是叙述，允许局部冗余。

## 字段表（按 tier）

### Tier 0 — 必有

| 字段 | 类型 | 来源 | 示例 |
|------|------|------|------|
| `姓名` | string | H1 | `步非烟` |

注：不用 `title`（保留给 MkDocs Material），不用 `name`（保留英文位）。

### Tier 1 — 基础属性（lint 显示 25%+ 出现）

| 字段 | 类型 | 覆盖率 | 示例 | 备注 |
|------|------|--------|------|------|
| `性别` | enum | 75% | `女` | 取值：`男` / `女` / `其他` / `不详`。注意不要写 `null` |
| `初登场` | string | 58% | `霹雳侠峰 第48章` | 原文字符串，不拆剧集 |
| `根据地` | string \| list[string] | 46% | `圣龙口` 或 `[圣龙口, 岁月如楼]` | 多个用 list |
| `退场` | string | 34% | `霹雳侠峰 第48章（受天道主书信所托）` | 含死因/原因 |
| `称号` | string \| list[string] | 28% | `凤舞凌云` | 诗号式称号 |
| `配音` | string \| list[string] | 26% | `黄文择` 或 `[黄文择, 萧亚辉]` | 多人配音用 list |

### Tier 2 — 别名 / 身份（合并去重）

| 字段 | 类型 | 来源字段 | 示例 | 备注 |
|------|------|----------|------|------|
| `别名` | list[string] | `别名` (19%) + `本名` (3%) | `[伏夜笙]` | 同义合并，去掉「中文名」「名称」（=H1） |
| `身份` | string | `身份` (17%) | `紫微旗主` | 功能角色（vs 称号=诗意） |
| `诗号` | string | `诗号` (6%) | `凤舞凌云...` | 角色诗号，可多行 |

### Tier 3 — 能力（多值）

| 字段 | 类型 | 覆盖率 | 切分规则 |
|------|------|--------|----------|
| `武学` | list[string] | 19% | 按「、」「，」「\n」切，去括号注释 |
| `武器` | list[string] | 7% + `兵器` 3% | 合并这两个变体 |
| `所有物` | list[string] | 4% | |
| `咒术` | list[string] | 3% | |

### Tier 4 — 人际（嵌套）

合并多个亲疏关系字段为单一 `人际` map：

```yaml
人际:
  上司: [青阳子, 静涛君]
  同伙: [昔月影, 欧阳铁血]
  朋友: [普雨, 沙舟一字师]
  兄弟: []
  姐妹: []
  部属: []
  师徒: []
  仇敌: []
  其他: []
```

覆盖率：`朋友` 24% / `上司` 19% / `兄弟` 5% / `姐妹` 2% / `同伙` 2% / `部属` 2% / `其他` 4%。

约定：**空 list 不写**（v1 不强制必填）。

### Tier 5 — 组织

| 字段 | 类型 | 备注 |
|------|------|------|
| `组织门派` | list[string] | 合并 `组织门派` (15%) + `组织` (6%) + `门派` (3%) 三个变体 |
| `种族` | string | 6%，主要 dongli/pili 超自然剧情 |

### Tier 6 — 制作元数据（剧外）

| 字段 | 类型 | 覆盖率 | 示例 | 备注 |
|------|------|--------|------|------|
| `登场作品` | list[string] | 26% | `[霹雳侠峰, 霹雳邪章之道劫龙战]` | 所有出现作品（区别于 `初登场` 仅首次） |
| `本尊雕偶师` | string | 11% | `洪有聪` | 偶人雕刻师 |
| `编剧` | string \| list[string] | 6% | `太平` 或 `[黄强华, 王嘉祥]` | 角色编剧 |
| `出场集数` | string | 8% | `4集` | v1 保留原文，不拆 int |

## 不进 frontmatter（v1 保留正文）

- **`代表颜色` (34%)** — 偶人服装色，纯视觉
- **冗余字段**：`中文名` (31%) / `名称` (14%) — 跟 H1 = `姓名` 重复
- **`繁体标题` (12%)** — 编辑器元数据
- **dongli 特有的 `生日` `外文名` `季度`** — 留 v2 再统一

## v1 显式不做的事

| 不做 | 原因 |
|------|------|
| 拆 `初登场` 为 `{series, episode}` | 数据噪声大（"第48章" vs "第48集" vs "第三章" 中混乱），人工 1000+ 次校对成本高 |
| 武学名称标准化 / 去重 | 同一招式跨剧名称变体多，需要专家知识 |
| 跨 doc 引用一致性（提到 X 但 X 不在 frontmatter 列表） | 留给 lint.py 后续扩展 |
| 配置 MkDocs Material 自动 nav 用 frontmatter | 现有 awesome-pages 已工作 |
| 处理 dongli 特有字段 | 49 个 doc，单独迁移代价高，留 v2 |

## 实施 plan

1. `_tools/yaml_extract.py`：
   - 输入：`docs/角色/{brand}/*.md`
   - 解析 **bold**/行首字段，按 schema 表映射
   - 输出：dry-run 模式打印生成的 frontmatter；apply 模式原地插入
   - 已有 frontmatter 的 doc：merge 不覆盖（用户手动改过的优先）
2. 20 个 sample dry-run → 人工 review → 调 schema
3. 全量 apply（含 backup 到 `.pre_yaml_backup/`）
4. `mkdocs build --strict` 验证
5. commit + push
